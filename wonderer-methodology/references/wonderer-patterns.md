# Wonderer patterns

Adapted from Magnus Hedemark's wonderer-methodology in hermes-profiles at
commit `867a555e13bae53a3945aa5328b1e09d347268cc` (MIT). These patterns create
conditions for lateral discovery; they do not promise a novel or correct result.

## Seed framing

A territory description leaves multiple peripheries open. For example:

> One-person software businesses built from small codebases, APIs, and automation.
> The founder also operates the business, and attention is a scarce resource.

For an explicitly divergent request, this is more fertile than “How do solo
software businesses increase margins?” It opens questions about isolation,
dependency risk, attention, and the shape of a codebase. Do not widen a question
when the user actually wants it answered. A seed such as “technology” needs a
focused clarification before useful dimensions can be selected.

## Dimension decomposition

Choose 3–4 dimensions that fit; do not exhaust the menu.

| Dimension | Direction |
|---|---|
| Historical | Predecessors and earlier versions |
| Adjacent field | Similar structures with different practices |
| Contradiction | Places the territory undermines its own promise |
| Inversion | Reversed assumptions or constraints |
| Scale boundary | What changes at tiny or enormous scale |
| Human experience | What it feels like to inhabit the system |
| Hidden dependency | Necessary conditions that receive little attention |
| Implied future | What success or failure makes possible or removes |

For the solo-business seed, attention management, API dependencies, and absence
coverage are distinct directions; three billing variations are probably one.

## Lateral query patterns

One well-crafted query per selected dimension; at most four in a default pass.
The following are illustrative queries, not records of searches performed. Search
engines differ: use supported syntax, not a presumed universal Boolean language.

| Pattern | Illustrative query | Purpose |
|---|---|---|
| Collision | `solo software business cockpit design attention` | Put the seed beside an unexpected domain |
| Negative space | `solo software business -subscription` | Exclude an obvious association if the tool supports minus exclusions |
| Anti-precedent | `solo founder software business burnout failure` | Seek breakdowns rather than success narratives |
| Structural mirror | `one operator many automated systems air traffic control` | Search a shared structural burden in another field |

A query can yield no useful lead. Report the gap rather than invent a source,
repeat searches indefinitely, or treat an empty result as proof of absence.
Use generalized queries rather than private identifiers from the seed.

## Interesting and correct are separate axes

Ask whether a result opens an unexpected direction or challenges a seed assumption.
Defer deep evaluation, while retaining ordinary honesty about evidence. Record
retrieved facts with their sources, mark inferences, and mark generated analogies
as speculative. A fertile idea can remain unverified; a demonstrably false claim
must not be presented as fact just because it is interesting.

For example, cockpit design may suggest an attention-management analogy for a
solo operator. It does not establish that aviation practices reduce founder
burnout. The next research question could ask which attention constraints the
settings actually share, and where the analogy fails.

## Tether check

| Candidate | Assessment |
|---|---|
| “Air traffic control is interesting.” | Drift: no relation to the seed is stated |
| “A solo operator may face an attention-switching burden like that in air traffic control.” | Tethered analogy; the shared burden is explicit, but transfer remains untested |
| “Could handoff practices inspire a solo business's absence-coverage design?” | Tethered open question; it names the seed's continuity problem |

The tether should explain the connection in one sentence. A distant domain is
welcome when the connection is explicit; topical similarity alone is insufficient.

## Stop without forcing convergence

Stop at the query bound, repeated shapes, or the point where a lead needs deeper
investigation. Three to five distinct leads are a useful target, not a quota.
Return fewer if the evidence or seed supports fewer. Report unexplored dimensions
as gaps, not as an exhaustive map. Preserve the user's choice of what comes next;
route a selected investigation to research-methodology rather than an unavailable
researcher profile.
