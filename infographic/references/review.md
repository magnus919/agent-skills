# Review and polish

Inspect the actual final export at its intended viewing size and at detail scale.
A source file can be correct while its export clips text, substitutes fonts, or
makes essential annotations unreadable. Automated checks supplement visual review;
aesthetic confidence does not replace evidence validation.

| Gate | Pass evidence | Revise or block when |
|---|---|---|
| Purpose | Intended reader can find the promised answer/action | No clear takeaway or mismatch with reading context |
| Evidence | Claims trace to supplied/verified sources; calculations reproduced | Invented values, missing denominator, material limitation hidden |
| Encoding | Geometry and connectors reflect the stated relationships | Distorted magnitude, unsupported causality, false ordering |
| Hierarchy | Entry point and reading path support the main message | Competing focal points or decorative weight hides evidence |
| Legibility | Essential copy and marks readable at delivery size | Shrunk text, collisions, low contrast, ambiguous labels |
| Accessibility | Redundant cues and useful text/data equivalent | Color-only meaning or missing equivalent information |
| Craft | Consistent spacing, alignment, type roles and image treatment | Arbitrary gaps, uneven connectors, visible generation artifacts |
| Delivery | Correct dimensions/format, no clipping, required files exist | Missing export, broken assets, unsupported promised format |
| Comprehension | Reader feedback if tested; otherwise labeled heuristic review | Claimed user testing without a participant or result |

Fabrication, misleading encoding, wrong calculations, unreadable essentials, and
missing material context block ready-for-use delivery. Cosmetic excellence cannot
compensate. A blocked artifact can still be delivered as a clearly labeled draft
with the unresolved issue and a concrete next step.

## A useful inspection sequence

- Hide detail mentally: does the title and dominant visual say the right thing?
- Read every label and trace every connector. Compare all values to the ledger.
- Inspect incidental scene details for unintended instructions: a depicted device,
  setting, uniform, or clock can imply a required channel, place, authority, or
  duration. Remove or qualify unsupported details that change what readers do.
- Check boundaries: clipping, margins, crop, source footer, long words, symbols,
  decimals, multilingual glyphs, and smallest annotations.
- Compare repeated elements for alignment, scale, spacing, capitalization,
  precision, line weight, icon logic and corner treatment.
- Remove decoration that competes with meaning; retain illustration that earns its
  place. Increase useful contrast and breathing room before adding more effects.
- Re-export and re-inspect after repairs. Record which checks were actually done.

## Accessibility with scoped claims

For web delivery, WCAG 2.2 contrast guidance generally requires 4.5:1 for normal
text, 3:1 for qualifying large text, and 3:1 for essential graphical objects against
adjacent colors, with specified exceptions. Check the actual size/weight and use
rather than treating every label as “large.” Color cannot be the only carrier of
meaning. Pair it with labels, patterns, shapes, or positions that survive loss of
color. Simulations help detect problems but do not prove compliance.

Complex images need a useful summary plus detailed equivalent information as
appropriate, including relationships and data. Consider reading order, language,
zoom, and cognitive load. Do not claim comprehensive accessibility certification
from a palette check or a single screenshot.

## Finish with an honest review note

Report the delivered files, their use/size, source provenance, key checks, and
remaining limitations. Distinguish factual verification, mathematical checks,
heuristic visual inspection, and actual reader testing. If you could not render or
view a result, say exactly which properties remain unverified.
