# Reference-Led Visual Direction

Read when visual identity is unsettled, a person gives vague aesthetic feedback,
or generated assets drift from an approved brand. Use existing strategy and assets
first; a small asset request does not require rebuilding the whole brand book.

## Elicit intent without requiring design jargon

Ask about audience, communication purpose, intended feeling, practical placement,
existing assets and non-negotiable constraints. Accept a rough or dictated brief;
extract a concise working brief and identify only consequential missing inputs.
Do not force the person to select exact fonts or hex codes before exploring.

Offer a few meaningfully distinct references or mood directions, not a large batch
of cosmetic variations. Ask which specific property works: color relationships,
typography, image treatment, density, tone, or hierarchy. Capture disliked properties
too. Explain tradeoffs in ordinary language. Inspect supplied references when tools
permit; state when you have not seen them rather than inventing visual details.
A reference is inspiration, not permission to reproduce someone else's logo or assets.

## Establish a style guide, then support a system

For a new identity, establish enough approved visual direction to guide the task:
color roles, typography hierarchy, spacing, shape, imagery and usage examples.
Label unchosen options as proposals. Do not invent exact production color values,
font licenses or approval evidence. Build on existing approved identity when present.

A style guide describes the visual language. A design system also needs reusable
components, states and behavior. Route product behavior to `product-design-and-ux`
and component implementation to `frontend-engineering`; do not call a palette or
a page of screenshots a complete design system.

## Refine and preserve

Use an editable composition when placement, typography or exact geometry matters.
Diagnose feedback by layer before regenerating the whole artifact. Keep the accepted
parts fixed while revising the named issue. For logos or scalable graphics, determine
whether the deliverable needs genuine editable vector geometry, a raster reference,
or both. A bitmap embedded in an SVG is not editable vector artwork; a generated
concept still needs production checks, correct exports and any necessary rights review.

Preserve the selected source revision, rationale, actual approval scope, rejected
directions and unresolved details in the existing visual identity/governance records.
Keep canonical examples and rules small and local to their use. 'Looks good for this
mockup' does not approve every element for all channels, change the brand globally,
or authorize publishing. Do not silently turn a one-off preference into a lasting rule.

## Practical example

A founder likes a reference's calm spacing but dislikes its pale text. Preserve the
spacing hypothesis, propose readable text treatments, and compare them in the actual
small-screen placement. Once a direction is accepted, record the relevant token roles
and example revision. Do not copy the reference's logo or claim the result is accessible
from appearance alone; use `web-accessibility` for conformance testing.

## Completion

Deliver the scoped style guidance and approved/reference artifacts, with proposed
choices and remaining production checks clearly separated. Use a bounded revision
loop; if feedback is not converging, show the unresolved tradeoff and ask the smallest
question that unlocks it. Stop when the requested identity artifact is usable, not when
every possible brand template has been filled.
