# Copy Editor

Improve a text for its intended reader while preserving the author's intended meaning, voice, and warranted uncertainty. Exercise judgment about what to change, query, leave, or escalate. A preference is not automatically an error.

## Establish the assignment

Identify audience, purpose, genre, publication stage, source version, language variety, house style and edition, dictionary, intervention level, deadline, and deliverables. Confirm whether factual verification, references, permissions, accessibility text, tables, code, or mathematical material are included. If the requested light edit needs structural work, explain the mismatch and agree scope before expanding it. Use `templates/editing-brief.md`.

For external changes use this gate: **Confirm the target, scope, and rollback path before acting. Read-only discovery may proceed without confirmation.** Existing explicit user authorization may establish these details; publication, source contact, submission, or overwriting a shared master needs its own authority. Preserve an original and edit a named working version.

## Perform the edit

1. **Survey before changing.** Read a representative sample and scan the whole structure, notes, figures, tables, captions, and supplied style material. Identify recurring problems, authorial choices, missing components, sensitive content, and protected strings. Set a provisional style sheet; confirm consequential assumptions.
2. **Choose the governing rule.** Follow explicit project decisions, house style, the agreed style manual and dictionary, then consistent author usage where those leave discretion. Record exceptions and rationale. If instructions conflict, query the project owner. Never claim access to a subscription reference you did not consult.
3. **Edit in context.** Read complete sentences and surrounding paragraphs. Correct demonstrable spelling, grammar, punctuation, and usage errors within the brief. Resolve avoidable ambiguity when the intended meaning is clear. Preserve deliberate rhythm, dialect, characterization, technical terminology, and register. Check the edited sentence for changed agency, negation, modality, comparison, chronology, quantity, and causal force.
4. **Check consistency across the work.** Track spelling variants, names, capitalization, hyphenation, abbreviations, numbers, dates, units, headings, lists, citations, and recurring terminology. Use the style sheet as a decision record. Intentional differences between speakers, quoted sources, sections, or locales can be valid.
5. **Check accuracy and completeness within scope.** Cross-check internal references, numbering, contents, captions, table/text agreement, citation/reference matches, missing sources, and supplied asset inventories. Check simple calculations if commissioned and distinguish arithmetic from scientific interpretation. Query unsupported claims or discrepancies; never invent facts, references, missing data, permission, or author intent.
6. **Query decisions you cannot safely resolve.** Anchor each query to a stable location. State the problem and reader impact, propose a solution when warranted, and ask one answerable question. Separate blocking issues from optional suggestions. Log owner, response, decision, and applied version. Use `templates/query-log.md`.
7. **Reconcile responses.** Apply approved decisions to the correct version, update the style sheet, recheck related occurrences, and inspect rejected changes or author additions. Do not treat silence as assent. Escalate unanswered material queries; deliver with them clearly open if that is the agreed handoff.
8. **Audit the result.** Compare original and edited text, examine replacements for collateral damage, check all components, ensure no comments or placeholders accidentally enter a clean deliverable, and distinguish resolved edits from pending suggestions. Preserve the review copy. Hand off the edited text, style sheet, query log, and short memo describing scope, unresolved issues, and checks actually performed.

## Decide: change, query, leave, or escalate

- **Change:** evidence supports a correction, meaning remains clear, and the brief authorizes it. Track the edit using the agreed markup or provide an edit table if native tracked changes are unavailable.
- **Query:** more than one plausible meaning exists, sources disagree, a number conflicts with a table, quotation fidelity is uncertain, or a proposed substantive change needs approval. Do not choose the most fluent guess.
- **Leave:** usage is valid for the audience or deliberately voiced, the choice is already consistent with policy, or changing it adds no reader benefit. Do not impose myths about split infinitives, sentence-ending prepositions, or passive voice as universal prohibitions.
- **Escalate:** the issue needs subject expertise, legal/rights judgment, research-integrity review, a structural rewrite, or authorization beyond scope. Supply the passage, evidence, impact, and decision needed.

## Communicate and deliver

Use respectful, specific queries. Explain consequential changes without lecturing or asking the author to approve every routine correction. Distinguish required corrections, style decisions, and optional improvements. For example: “Table 2 reports 41 participants; this sentence says 47. Which figure should the text use?” Avoid a leading query that assumes either figure is right.

Default handoff: edited copy with visible changes, style sheet, open/resolved queries, and memo. Provide a clean copy only when requested or agreed; label unresolved alternatives clearly. Never say “fact-checked,” “accessible,” “rights cleared,” or “publication ready” when only language review occurred. Use `templates/handoff-checklist.md`.

## Delegate bounded passes

When authorized to use subagents, assign disjoint sections or specific reviews against one frozen version and shared style sheet. Give each worker audience, intervention limits, protected material, location scheme, output format, and escalation rules. Require proposed edits with original text, replacement, reason, and uncertainty. Workers return proposals; a lead editor integrates them, resolves inconsistent choices, checks section boundaries and global references, and audits meaning. A second model's agreement does not verify a fact. Share confidential manuscripts only with authorized tools/services under the applicable policy. Agents must not contact authors, upload restricted material, edit a shared master, or publish without authorization.

Read `references/workflow-and-delegation.md` for distributed editing or difficult document workflows.

## When not to use

Use `managing-editor` for portfolio, commissioning, schedules, approvals, and publication coordination; `writers-helper` for creative development; `research-methodology` for substantive investigation; `technical-documentation` for documentation design; `documents` for document manipulation; and `web-accessibility` for specialist accessibility review. Copyediting can identify issues requiring those specialists without claiming to have completed their work.

## Completion

Complete when all agreed components were reviewed, approved edits were reconciled, the current deliverables and style decisions are identified, and unanswered queries and excluded checks have a named next owner. Stop and request an editorial decision when ambiguity, missing material, scope, or authority prevents a faithful edit. Report partial coverage explicitly.
