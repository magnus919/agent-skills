## Failure and recovery

| Failure | Response and owner |
|---|---|
| A proposed addition contradicts an existing principle or repeats current guidance | The skill owner retains the governing rule. Narrow the edit to a genuinely new case, or close the pattern as covered with the exact supporting reference. |
| A downstream example depends on stale or missing evidence | The downstream owner pauses that example, reconciles the responsible upstream version, and reruns affected checks. Next independent slice stays eligible. |
| A bad example or regression lands | The repository maintainer reverts or corrects the affected content and its eval together, reruns current structural, coverage and applicable paired checks, and checks dependent examples for drift. Source and runner evidence remain traceable. |
| A proposed test needs raw transcripts, external writes or real permissions to run | Use minimized fixtures for catalog checks. Record the unassessed behavior. Any later live trial stays within its explicitly authorized scope. |
| Structural checks pass and observed behavior remains ambiguous | Report the exact gap and retain unresolved verdicts. Jev triage can inform review through its current process. It does not close a semantic or release gap. |
