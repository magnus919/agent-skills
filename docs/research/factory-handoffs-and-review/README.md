# Factory handoffs and useful review

**Question (2026-11-26):** Which controls from the ZazenCodes software-factory demo merit portable skill guidance, and which claims still lack outcome evidence?

**Finding:** Separate a job's recorded intent and artifacts, its review verdict, authorization to integrate, compatibility with the current target, and confirmed delivery. Keep cheap executable checks ahead of costly judgment where they answer the same prerequisite; reserve specialist review for material exposure. Measure the value of review by what changes in the resulting candidate, not by agents launched or comments emitted.

- **Harness Engineering:** A worked incident makes a common boundary tangible: separate build folders did not isolate the merge operation. Give the integration lane its own clean environment; distinguish a merge blocker from a decision waiting on a person. Record the candidate, target or merge-group revision, current checks, and post-merge proof.
- **Spec-Driven Development:** In the existing review lanes, run an applicable cheap executable prerequisite before models; distinguish checked behavior from untested consequences. Missing evidence, implementation defects, and policy decisions each have different owners.
- **Agent Evals & Observability:** Compare reviewer configurations on the same pinned candidates. Count distinct confirmed findings (including important misses) separately from whether revisions fix them without regressions. Report all-in burden and unresolved cases. Evidence supports measuring these outcomes, not prescribing a universal topology.

See the [evidence ledger](evidence.md) for sources, method, limits, and exclusions. No Anthropic model, proprietary harness, fixed reviewer count, or automated deployment is a prerequisite.
