# Safe cohort result workflow

## Workflow

First define the requested distribution, source owner, intended downstream app, authority for both sources, and the cohort’s identity and time boundary. Fetch every page of the source query, following each continuation cursor until an explicit terminal state. Persist the response pages or a materialized immutable cohort with source, query fingerprint, snapshot/revision, time window, page/cursor history, exact count if the source guarantees it, and a content hash. The artifact must report `complete`, `partial`, or `unknown`; page one is never labeled complete merely because it returned successfully. Keep records outside model context and expose bounded page, projection, filter, and aggregate operations.

Represent the source key as a namespace-qualified tuple, such as `(source, tenant, record_id, record_version)`. A stored opaque handle is a retrieval reference, not a portable customer ID or proof that another application can access it. Before joining, require an explicit, authorized identity mapping owned or verified by the relevant systems. Record mapping version, match basis, confidence only if it has a defined meaning, and each outcome: matched, unmatched, duplicate, conflicting, or unresolved. Do not join by display name. Preserve source snapshot/time-window differences because they can change the cohort and join meaning. The receiving app should get a separately authorized transfer or supported mapping step; access to the original artifact does not imply permission to disclose it cross-service.

## Handle expiry and resume

The handle contract must declare principal/tenant scope, sensitivity, expiry, retention owner, and behavior after revocation or expiry. On resume, validate the handle and reauthorize access before reading. If it is expired, do not silently rerun the original query and imply the same cohort. If the source offers the same immutable snapshot, recreate the artifact from that snapshot and identify it as a regenerated version. Otherwise request or perform an authorized fresh query, label it a new cohort with a new snapshot and fingerprint, and explain that membership may differ. If authority is absent, stop with a denied state and a safe next step.

## Completion contract

Completion requires evidence that all pages were consumed, the artifact is complete with a count and provenance, identity mappings were applied only under an approved mapping contract, unmatched and duplicate records were accounted for, and the downstream app actually consumed the intended artifact or mapped output. Report the resulting distribution with cohort definition, denominator, excluded/unmatched counts, source snapshots, join version, and computation identity. A response saying the handle was passed does not prove consumption. A sample is illustrative only.

Challenge the workflow with partial pagination, repeated/omitted cursor pages, page timeout, duplicate rows, source mutation, wrong tenant, denied downstream access, incompatible schema, expired handle during resume, and a join with duplicate identifiers. Inspect runtime state to verify no records were lost, duplicated, or exposed outside scope. Include a process interruption after artifact creation and before acknowledgement; resume should return the same durable artifact if still valid, not rerun into a different result. Record tested failures and untested assumptions. Keep transfer, storage, and computation bounded, authorized, and auditable. Do not claim the reported distribution is reliable while completeness, identity resolution, or downstream consumption remains unknown.
