# Comparison and release decision

The demo and reduced token counts support only a narrow observation: one demonstration completed and measured context use fell under unspecified conditions. They do not establish that tool discovery or external result handles improved task success, reliability, safety, or total cost. Treat these as two mechanisms with separate hypotheses. Discovery may reduce irrelevant definitions while still finding the correct operation and prerequisites. External handles may keep large payloads out of context while preserving completeness, authorization, provenance, and actual downstream consumption. If both changed together, use separate arms or ablations; otherwise interpret only the bundle.

## Design

Freeze baseline and candidate configurations, model/runtime, service/tool versions, identities and permissions, task and result semantics, resource policies, grader versions, and dataset before the decision run. Use paired realistic tasks under comparable initial state. Include task-relevant search, irrelevant/ambiguous requests, near-duplicate tools, stale/no-match index, missing prerequisites, paginated results, partial pagination, and a fresh session repeating a task. Include external-handle delivery to a downstream consumer that must actually read it. Challenge missing, expired, wrong-tenant, revoked, stale, duplicate, partial, and consumer-inaccessible handles. Include a permission-denied case: the agent must surface denial, avoid alternate-route evasion, and never count the attempt as successful. Run repeated trials where stochastic behavior could change the decision. Keep failures, denials, timeouts, partial outcomes, and missing observations in the denominator.

Create immutable, versioned cases with provenance, rights/consent, fixture reset, expected side effects, contamination risks, limitations, and retention. For each task define intended end state, prohibited outcomes, permitted tools/authority, required trajectory evidence, and completion oracle. Grade end state and side effects from environment state; inspect traces for discovery, prerequisite order, authorization, artifact creation/retrieval, downstream use, and recovery. Use deterministic checks for counts/IDs and human or domain review where semantic judgment is needed. Ensure graders can distinguish missing evidence from failure and success.

## Measures and decision

Report paired task outcomes by slice; correct discovery and prerequisite ordering; result completeness and integrity; actual authorized downstream consumption; unauthorized calls/disclosures; false completion claims; retries, duplicates, recovery, and timeouts; context/tokens; latency distribution; and monetary, storage, transfer, orchestration, and cleanup cost only from valid meters. Token reduction is a resource measure, not a cost or quality proxy. Preserve case-level discordances, effect sizes, uncertainty intervals, grader disagreement, missingness, and confounders. Choose repeats and sample size for the risk and minimum effect that would matter; do not use non-significance as equivalence.

Hard release blockers include unauthorized actions or disclosure, evasion after denial, silent partial results, unreconciled harmful effects, and false completion. These cannot be averaged against lower token counts or faster latency. Hold for insufficient evidence if the comparison lacks representative task outcomes, fresh-session recurrence, denial behavior, or artifact-consumption proof. Conditional approval needs an owner, containment/rollback, monitoring, expiry, and review trigger. Broaden release only after the candidate passes the predeclared task and hard-invariant rules on held-out or otherwise uncontaminated cases, with live client/service evidence for claims that mocks cannot establish. Preserve failures as regression cases after privacy and rights review.
