# Safe cohort analysis with resumable artifacts

The intended outcome is a complete, correctly joined distribution over the authorized cohort, with enough evidence to resume safely and reproduce the result. A page-one sample is not a completed cohort. A stored handle is not proof that its contents are complete, current, authorized, or joinable to another app’s identities.

Before querying, record the requested cohort definition, source owner/revision, authorization scope, intended output, retention boundary, and join purpose. Fetch every page using an opaque cursor and a stable snapshot or query revision. Persist each page’s cursor in/out, count, checksum or stable IDs, timestamp, and source revision. Detect repeated cursors, missing pages, duplicate IDs, and snapshot drift. Continue until the provider’s explicit terminal cursor; do not infer completion from a short page or expected count. If the source cannot offer snapshot consistency, disclose that limitation and define how changes during pagination are handled.

Treat the cross-app join as a separate governed transformation. Establish the approved identity mapping source and its owner, permitted fields, freshness, and one-to-one/many-to-one semantics. Do not equate unlike identifiers by string similarity or assume stored handles imply identity compatibility. If mapping is absent, ambiguous, stale, or outside scope, stop and report the unresolved dependency. Minimize transferred data, keep identifiers protected, and record the mapping version and join coverage. Validate unmatched, duplicated, and ambiguous identities before computing a distribution; expose the denominator and exclusions.

Use durable state containing task ID, cohort query and source revision, identity-map revision, authority, page ledger, counts, terminal cursor, artifact handle and expiry, transformation version, output hash, status, evidence references, and next action. A handle expiring during resume should transition the task to “artifact unavailable/needs re-fetch,” not silently produce an incomplete analysis. Re-fetch only if the query is reproducible and still authorized; otherwise request a new approved run. Before any retry, inspect source and operation status so a timeout is not confused with no effect. Publish a completion pointer only after all pages, join validation, and output have been durably recorded.

Completion requires evidence that every page in the stable source snapshot was collected, counts reconcile, the approved identity map was applied, join/exclusion rates are reported, and the result’s denominator and distribution can be reproduced from retained authorized artifacts. A reviewer should be able to distinguish complete, partial, blocked, and stale states. Inject failures after page retrieval, during checkpoint writing, after artifact expiry, and before acknowledgment. Recovery must avoid skipped or duplicated pages and reject stale workers. Keep raw IDs under appropriate access and retention controls; return only the minimum aggregate output. If completeness, permission, or identity linkage cannot be demonstrated, label the result incomplete and do not report it as the cohort distribution. Preserve rollback by invalidating the derived result and retaining the original source query record for a fresh authorized run.
