# Repair the agent’s discovery path

Treat these as three observable failures with potentially different causes: a channel-name/ID mismatch, stale search index behavior, and authorization denials. Do not respond by adding a broad instruction such as “use tools correctly,” retrying denied calls through another tool, or rewriting the whole harness. The smallest plausible repair is to improve discovery and call contracts at the point where the agent chooses tools, while first collecting one representative trace to confirm the first divergence.

For message search, make the distinction between human-readable channel names and canonical channel IDs explicit in the tool schema and description. If the service can resolve a name safely, expose a read-only resolver returning the canonical ID and a confidence/ambiguity status, then require the search operation to take the ID. If name resolution is already available elsewhere, route the agent there before search. Return typed invalid-input errors that say which identifier form is required and provide a safe recovery path. Do not guess among ambiguous channels. Acceptance is an authorized search against a known fixture channel using its ID, plus a negative case where a name is passed directly and is rejected with actionable guidance. Compare the actual selected tool and arguments in the trace, not merely the final answer.

For catalog search, determine whether the index’s revision or freshness metadata is available. Return source/index revision and an explicit stale or unavailable status; distinguish “no matches in current index” from “search failed” and from “access denied.” The smallest repair may be an index refresh or a bounded fallback to the authoritative source when the index is stale, with provenance attached. Avoid silently returning empty results on stale state. Test a current-index match, a true zero-match query, and a deliberately stale-index fixture. Verify the returned source revision and the recovery path. A fallback is still subject to the same scope and permissions.

For denied tools, preserve the denial as a terminal authority signal. The agent should stop the affected operation, state that access was denied, and identify the authorized owner or permission request route if one exists. Never retry with a different tool or broaden the query to evade policy. Exercise a denied fixture and inspect the trajectory for no alternate call and no side effect.

First-divergence evidence should include the task, agent/configuration revision, tool descriptions and schemas, permissions, source/index revision, chosen tool and exact normalized arguments, returned status, and final completion claim. Competing explanations include poor tool descriptions, stale context, resolver absence, and upstream service failure; one controlled same-task probe should discriminate them. Record rollback as reverting only the affected descriptor/resolver/index-routing change. Acceptance requires correct selection and argument formation, visible distinction among empty/stale/denied results, and no false completion. Keep behavioral claims bounded until the same cases run against the baseline and candidate with comparable conditions; structural changes alone do not prove improved discovery.
