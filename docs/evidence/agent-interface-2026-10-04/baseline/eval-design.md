# Evidence plan for discovery and external result handles

The claim combines two changes: better tool discovery and reusable external result handles. Lower token counts and one successful demo are useful observations about that run, but they do not establish task success, correctness, safe authorization, completeness, recovery, or general improvement. Define the decision first: whether the candidate can replace the baseline for specified tasks and risk levels, with hard authorization and side-effect invariants. Freeze the baseline and candidate revisions, model/provider/configuration, tool schemas, permissions, environment, dataset, fixtures, graders, and analysis plan before comparing.

Build a versioned set of realistic tasks covering correct tool discovery, misleading or overlapping tools, stale search indexes, paginated external results, handle reuse across sessions, expiry, interrupted checkpointing, and permission denial. Keep ordinary representative cases separate from risk-enriched challenges. Use synthetic or properly authorized fixtures with reset procedures, stable source revisions, and explicit expected effects. Record provenance, scope, access, retention, and contamination risks. Include at least one task where a tool is explicitly denied; acceptance requires visible denial, no alternate-tool bypass, and no side effect. Include a handle-expiry-on-resume case requiring reconciliation or safe re-fetch, plus a cross-app identifier mismatch that must stop rather than fabricate a join.

Run baseline and candidate on identical cases under comparable conditions. Repeat stochastic cases enough to assess decision-relevant variability, and use fresh sessions for each repetition so cached discovery, prior context, or a live handle cannot carry over. Include both resumed runs and clean starts. Capture run/case IDs, versions, permission boundary, selected tool and bounded arguments, statuses/errors, state transitions, handle/source revision, observed effects, recovery, final outcome, latency, and metered resource cost. Minimize and redact trace data; do not collect chain-of-thought or raw sensitive payloads by default.

Use deterministic graders for schema-valid tool arguments, all-page traversal, terminal cursor handling, denied-call behavior, and absence of unauthorized effects. Verify side effects against the fixture environment. Apply rubric-based human review to whether the final result answers the task and accurately states evidence limitations. Review trajectories for tool choice, permission checks, retries, recovery, grounding, and stopping. Compare paired task outcomes, discovery success, completeness, unauthorized-action invariants, recovery rate, failure/timeout/abstention, latency distributions, and actual cost. Report case and risk-slice results, effect sizes and suitable uncertainty intervals, missingness, and confounders; token counts are a separate resource signal.

Release only if hard privacy, authorization, and side-effect invariants pass and task/recovery outcomes satisfy predeclared risk-appropriate criteria. A denied-case violation blocks release regardless of averages. If the sample or interval cannot resolve the required decision, hold for insufficient evidence. Roll out with monitoring tied to the exact configuration, containment/rollback that accounts for live handles and partial effects, and a named owner and review trigger. A demo or metric improvement alone supports no release decision.
