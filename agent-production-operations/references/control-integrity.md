# Control-integrity operations

Use before consequential execution, worker launch, and recovery when mandatory
controls supervise the workload. Consume ai-governance's protected-control registry;
security owns external enforcement and harness-engineering owns launch integration.
This procedure is not a named-tool runbook or a claim that a receipt enforces itself.

1. Resolve the current workload, parent/children, action class, grant, expiry and
   revocation status. Identify every applicable mandatory control and registry
   version. Recheck on resumption, control/configuration changes, scope expansion,
   or expiry; an old receipt cannot authorize new work.
2. Obtain evidence from the enforcing system or an independently controlled verifier:
   deployed monitor and policy identity, coverage scope, signal freshness, audit sink
   reachability, expected alert recipient and acknowledgement, kill-switch/revocation
   availability, and evaluator/gate integrity where applicable. Do not accept an
   agent assertion, configuration file alone, or an old successful run as live proof.
3. Bind a receipt to the exact workload, action scope, control/configuration versions,
   evidence IDs and times, verifier identity, permitted interval, revalidation triggers,
   and hold/contain/terminate disposition. Use risk-appropriate harmless canaries or
   authoritative status evidence; do not send real harmful actions to test controls.
4. Admit consequential execution only when required evidence proves controls active
   and applicable. The runtime launch/action boundary must enforce this decision
   outside the controlled agent's writable authority. Missing or stale evidence is
   insufficient evidence, not assumed active. Prevent time-of-check gaps with a
   bound launch token or equivalent external check; invalidate on relevant changes.
5. Missing, degraded, redirected, or suppressed mandatory controls trigger a
   control-integrity incident immediately. Hold affected consequential work; contain
   or terminate under the approved incident plan. Escalate via a protected alternate
   channel if the normal alert route is affected. Record attempts and observed state,
   preserve minimal authorized evidence, and block uncovered child launches.
6. Recovery preserves revocation and independent monitoring. Do not disable either
   to make restart succeed. Verify revoked credentials cannot act; verify restored
   controls and alert delivery externally; require the accountable authority's
   disposition and a fresh receipt before resuming. A bounded human maintenance
   exception must include scope, expiry, rollback, independent compensating controls,
   and restore evidence; consume it, never invent or approve it.

These incident rules take precedence over ordinary repeated-breach and health
thresholds. A read-only fallback is allowed only if the incident plan authorizes
that scope and its mandatory controls remain proven active. Otherwise hold or
terminate it too. A correct task result or reduced cost cannot offset lost control.

Complete with the independent receipt and supported execution disposition, or an
incident handoff naming missing evidence and the responsible owner. Do not report
readiness merely because the template is filled.
